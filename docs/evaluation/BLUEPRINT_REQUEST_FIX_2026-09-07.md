# 蓝图生成 HTTP 500 修复

版本保持 0.9.0。修复已部署 AutoDL，API 已重启，OIDC、RLS、S3 和 Ollama 保持启用。

## 实际原因

服务器 traceback：`enqueue_job` 抛出 `ValueError: Job idempotency key was reused with a different payload`。
页面在失败或等待后保留旧幂等编号，用户改变材料、模型或模板时仍使用旧编号。服务正确拒绝冲突，但未将异常映射为客户端可处理的响应，因此返回 500。

## 修改

- 请求编号绑定组织、项目和完整请求参数快照。
- 同参数网络重试继续复用编号，避免重复模型调用；参数变化创建新编号。
- 失败、取消、死信终态明确释放编号，不再只依赖错误文本语言判断。
- `JobIdempotencyConflict` 保持 ValueError 兼容，普通查重和并发冲突路径均使用该类型。
- HTTP 层返回 409、`job_idempotency_conflict` 和可读提示，不暴露其他任务内容。
- 前端识别冲突并为下一次用户提交释放旧编号，不静默重放写请求。
- 更新静态缓存标识，不变更产品版本号。
