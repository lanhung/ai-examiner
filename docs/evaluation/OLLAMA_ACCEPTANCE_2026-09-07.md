# Ollama 实机与浏览器验收报告

日期：2026-09-07。应用版本保持 0.9.0。本轮是启动与验收，不是新版本发布。

## 结论

AutoDL 上的 Ollama 已启动，现有模型可实际推理。基础功能可运行，但**尚不能认定全部产品功能与评分质量通过验收**。真实测试发现语义等价答案评分波动、材料不足时的出题与扣分问题，以及工作台登录失效后状态未及时更新。

本轮模型测试没有使用 Mock。既有自动化回归使用隔离测试替身，单列为软件回归证据，不能替代真实模型质量评测。

## 浏览器实测

在真实公网工作台，使用已有企业账户登录，测试数据均为合成非敏感材料：`examples/ollama_acceptance.md`。

1. 企业登录、控制台总览与返回工作台成功。
2. 创建 `Ollama真实验收-20260907`；会话过期后上传失败，见问题 P1-03。
3. 重新登录，创建 `Ollama网页复测-20260907`。
4. 通过文件选择器上传 Markdown，页面显示 262 字符、1 页、2 个证据，预览索引加载成功。
5. 选择 `Ollama Qwen2.5 14B`，异步生成 6 题蓝图成功，进度 100%，页面显示约 31 秒。
6. 启动文本答辩成功，回答后能显示评分并提出追问；该回答评分存在质量问题，见 P1-02。
7. 视觉选择器不提供这些纯文本 Ollama 模型；语音仍使用单独的云端实时模型配置，未冒充本地语音测试。
8. 只勾选 Ollama 14B 作为标注与共识模型，在页面生成 4 题 Golden Dataset 成功，数据集 ID `a4b4bd22-7fe6-4eb5-972a-5ba423aba0b9`，状态 `ready`。
9. 点击“运行多模型基准”，本轮实际只选择 14B。页面完成 Planner/Analyzer 基准：综合质量 **64.81**、Planner **65**、Analyzer **64.61**、总模型延迟 **222.14 s**、估算 API 费用 **$0.0000**。这是单模型、小型 AI 合成数据集的相对指标，不是专家准确率，也不是与其他模型对比后的第一名。

数据集 UI 显示来源匹配、字段完整和文本卫生均 100%，AI Panel 4.9，但四题全为 `method`，类型覆盖只有 1。来源字符串匹配不等于推理正确，单模型面板也不是独立评审。UI 的 $0 为本地模型 API 计费，不包括 GPU 租赁和电费。

本轮浏览器没有完成全部 7 种模板、多角色隔离和完整语音链路。完整会话终态通过的证据来自独立真实 Ollama API 流程，不与浏览器进度混为一谈。

## 发现的问题及优化方案

### P1-01：语义等价回答评分波动

问题：如何防止训练数据泄漏到测试评估中？

回答：留出的样本只在最终验收使用；均值方差只由开发用的训练样本估计，验收数据不参与参数估计。

首次输出同时出现 `semantic_match=equivalent`、`raw_status=missing`、空 `answer_quote`、`functional_criterion_satisfied=false`，最终 coverage 0.5、评分 2.2/5；复测 coverage 1.0。

建议：增加结构化语义结论冲突检测；发现冲突时降置信度并触发有限复核，不直接把任何 equivalent 自动转为满分。建立至少 30 组等价改写，每组重复 3 次，报告分数波动、误扣分率和错误答案误放行率。不能只增添本例关键词。

### P1-02：材料不足被错误转化为答题者不足

隔离流程中，部分预期答案包含原文未说明的“特定预处理技术”或“交叉验证”。浏览器第一题要求解释准确率提高的具体方法，但合成材料没有算法细节。测试回答明确说明提升 5 个百分点、材料不足以归因、缺少跨数据集验证，仍得到 0.8/5，并继续要求提供原因数据。

这不是断言该回答应满分，而是当前流程缺少“题目无法仅凭材料回答”的区分。

建议：Planner 为材料事实、合理延伸和待确认信息分开标注；Rubric 不得把未经支持的方法设为必答事实。Analyzer 接受有依据的“材料未说明”，转为澄清/研究设计追问；疑似出题缺陷先复核，不直接计入学习者知识缺口。

补充：另一次蓝图题干暴露了 `(objective_id: ...)` 内部标记，并堆叠多个任务。应在生成后进行题干格式与单主问题门禁，不能只验证 JSON 格式。

### P1-03：登录失效后工作台仍显示已登录

创建项目后停留一段时间，上传返回 `authentication_required: Authentication is required.`，顶部仍显示账户身份。进入企业控制台后显示未登录，重新走 OIDC 登录后上传成功。

目前证据支持“会话失效后的 UI 恢复不足”，不支持断言权限绕过或上传接口永久故障。

建议：统一处理 401，显示重新登录入口，保留非敏感表单上下文。不要静默自动重放上传/创建等写请求，以免重复提交。补充过期会话、重新登录、上传重试的浏览器回归。

### P2-01：辅助 Ollama 未纳入企业启动流程

现有普通 AutoDL 启动脚本仅在默认 provider=ollama 时启动 Ollama；当前默认 qwen，企业启动不会因此拉起本地辅助模型。服务器重启后可能再次显示本地模型不可用。

本轮先手动启动服务，并新增独立幂等入口 `deploy/start-ollama.sh`。已通过服务器 `bash -n`，连续两次调用均复用已有健康服务。没有为测试停止正在使用的服务，因此新脚本的冷启动分支尚未进行故障注入验证。之后仍需显式接入主机启动流程；不能为此悄悄修改整个项目默认模型，也不能对外暴露无认证 11434。

### P2-02：数据集 ready 门禁不保证题型覆盖

真实 4 题数据集只有 1 种题型仍标记 ready。建议按模板定义最小覆盖要求，区分结构可用与评测可用；单模型审查应显式显示独立性不足。小样本可以允许减少覆盖要求，但应标记为冒烟数据集，不能显示为完整质量验收。

## 复现与运行

进入服务器项目目录后，启动本地服务：

```bash
bash deploy/start-ollama.sh
curl -fsS http://127.0.0.1:11434/api/tags
OLLAMA_HOST=127.0.0.1:11434 ollama ps
```

辅助脚本重复运行不会停止已有健康服务，不下载模型、不修改 `.env`、不重启网站。它不是开机自启安装器，重启主机后仍需显式调用。

运行真实验收：

```bash
.venv/bin/python scripts/ollama_acceptance.py \
  --output logs/ollama-acceptance.json

.venv/bin/python scripts/ollama_acceptance.py \
  --only analyzer:paraphrase --only isolated_api \
  --output logs/ollama-followup.json
```

含失败用例时新脚本退出码为 1。第一轮原始脚本尚无此断言，不能用其退出码推断全部通过。

原始结果在服务器 `logs/ollama-acceptance-20260907.json` 和 `logs/ollama-followup-20260907.json`；本地镜像位于 `.ui-review/` 同名文件，仅为本次调试产物，尚未推送 GitHub。

## 尚需验收

- 7 个模板统一真实模型对照、多轮多次重复评分、知识记忆和复测质量。
- Golden Dataset/Benchmark 的跨模型质量与失败恢复；单模型浏览器链路本轮已通过，但不能把单模型自评当成独立专家共识。
- 持续并发、GPU OOM、服务重启、长上下文与限流故障恢复。
- 公网 PostgreSQL/RLS 的多租户、多角色负向测试，OIDC 全生命周期和 S3 下载权限。
- 真实麦克风/扬声器与 WebRTC：当前安装模型不支持，需独立测试云端语音或另行设计本地 STT/TTS 链路。

优先级：先修复材料不足与评分不稳定、登录过期恢复，再扩大模型和模板验收规模。不能宣称“全面通过”或“已经达到专家评分”。
