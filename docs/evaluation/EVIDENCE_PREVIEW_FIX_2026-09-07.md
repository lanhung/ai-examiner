# 页面证据预览修复验收

应用版本：0.9.0，未增加版本号。已部署到当前 AutoDL 实例。

## 根因

材料解析和证据索引成功，但原前端直接使用 `<img src="/api/evidence/.../file">`。
图片请求无法附带 `X-AI-Examiner-Organization`，受保护下载接口缺少组织上下文。
实机日志先出现 400，登录过期后出现 401；浏览器图片元素 `naturalWidth=0`、`naturalHeight=0`。
以前只根据证据列表成功返回就显示“已加载”，没有验证图片真正解码。

## 修复

- 通过带当前组织头和会话 Cookie 的同源请求获取图片 Blob。
- 有组织上下文时优先使用授权下载接口；保留本地非企业模式兼容。
- 保持后端权限、RLS 和存储访问约束，未开放公共文件地址。
- 下载成功还需图片解码成功，才计入预览成功数。
- 明确显示 401、403、404、非图片响应及解码失败。
- 最多并行 3 个预览下载；重新加载或切换组织时取消旧请求并释放 Blob URL。
- 更新静态资源缓存标识，不改变应用语义版本。

## 验证

- `pytest -q tests/test_enterprise_ui_v09.py tests/test_storage_backend_v09.py`：16 项通过。
- Node 前端契约覆盖组织头、会话 Cookie、本地模式、错误提示、无文件、非同源地址、无效图片、取消及资源释放。
- 后端回归确认缺组织上下文返回 400、错误组织无法读取、正确授权能下载 PNG。
- JavaScript 语法、Ruff、Git diff 空白检查通过。
- 公网浏览器重新登录，创建 `证据预览修复验收-20260907`，上传非敏感 Markdown。
- 图片实际解码为 **1280×720**，`complete=true`、`hidden=false`。
- 重复点击“加载证据”后仍显示“预览成功 1/1 页”。截图已目视确认缩略图可见。
- 实机日志两次授权图片请求均为 200。

## 使用说明与范围

旧标签页仍加载旧 JavaScript，需要刷新页面；如提示登录过期，重新登录后操作。
修复没有删除原上传文件或数据库记录。现有工作台不恢复刷新前的内存表单状态，因此应先保留未提交回答。

本次公网验证使用 Markdown 页预览；PDF/PPT 图片共用同一受保护下载与渲染链路，但未声称重新验收所有文件格式的解析质量。
前端原文件备份位于服务器 `logs/evidence-preview-backup-20260907/`。此次尚未提交或推送 GitHub。
