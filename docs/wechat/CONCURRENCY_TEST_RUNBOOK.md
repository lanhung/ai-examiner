# 小程序并发验收方法

## 目标与边界

目标场景为 20–30 人同班使用。需要区分三个指标：在线用户数、同时进行的 HTTP 请求数、同时调用大模型的任务数。它们不能互相替代。

本工具测量真实部署的 HTTPS 接口，不使用 FastAPI TestClient 或 mock 模型，不代表 30 台手机的渲染和网络体验。模型测试只使用 `qwen:qwen-plus`，不自动切换供应商。

脚本：`deploy/benchmark_wechat_capacity.py`。

## 安全约束

- 运行前取得创建合成账号和付费调用的许可。
- 从指定部署的 Uvicorn PID 读取运行环境，不打印密钥，不复制配置到报告。
- 使用普通 PostgreSQL runtime 角色；拒绝超级用户和 BYPASSRLS 连接。
- 独立创建一个测试组织、一个测试项目、31 个临时身份、30 份测试答卷。
- 考试始终为 closed，且预置答卷仅属于测试身份，不发布到真实学生的考试大厅。
- 这些身份是管理员建立的 HTTP 验收夹具，不是微信真实账号。本工具不测试 `wx.login`、code2Session 或新用户注册。
- 测试组织仅允许 qwen-plus，不允许 fallback；月度测试预算上限 2 美元。此值是应用侧估算预算，不等于供应商账单硬上限。
- 不修改正式组织的配额、成员、文件或成绩，不停用鉴权、RLS、审计。
- 每级最多 30 个并发请求；出现错误、响应超过 15 秒或健康检查失败时停止提高负载。
- 正常结束及捕获异常后撤销本次登录会话、停用测试身份和测试组织。保留关闭的测试考试、账单和审计数据以便追溯，不删除不可变审计。
- 超时未结束的本次蓝图任务会请求取消。进程遭到 SIGKILL、主机断电或数据库不可用时，自动清理不能保证，需要人工按报告中的组织 ID 检查。会话绝对有效期最多 30 分钟。

## 执行方式

在已授权的 Linux 部署中运行，使用已配置运行环境的项目 Python。报告路径必须是不存在的新文件。

```bash
cd /path/to/ai-examiner
.venv/bin/python deploy/benchmark_wechat_capacity.py \
  --root "$PWD" \
  --base-url https://your-approved-api-origin \
  --output /tmp/wechat-capacity-report.json \
  --users 30 \
  --confirm-synthetic-fixtures
```

增加 `--real-models` 才会执行付费阶段：3 个同时提交的合成考试答案，以及 3 个依次入队的真实蓝图任务。内部结构化输出修复可能产生额外模型调用，因此“三个任务”不等于“三次模型调用”。脚本不会自动重新提交失败的 POST。

服务器内的负载发生器与应用共享 CPU 配额。结果包含公网网关但不包含手机网络，且可能受到负载发生器自身开销影响；正式容量确认应补充独立机器发压。

## 测试阶段

1. 依次运行 1、5、10、20、30 个虚拟用户。
2. 每个用户每轮依次读取身份、考试大厅、自己的答卷。每级 3 轮，每轮之间等待 1 秒，级别之间等待 2 秒。这是短时闭环突发测试，不是持续满负载或恒定到达率测试。
3. 检查一个学生读取另一个测试学生答卷是否返回 404。
4. 可选：3 份真实答案同时提交，等待评分结果，客户端超时 65 秒。小程序原请求超时是 60 秒，故结果超过 60 秒时不能算手机体验通过。
5. 可选：提交 3 个不同幂等键的蓝图任务，同时执行 30 用户的两轮读取测试。
6. 每 5 秒查看任务状态，记录入队、开始和完成时间。等待上限 10 分钟，超时任务不作为成功。
7. 查询独立测试组织的用量账本和答卷状态，撤销凭据，保存 JSON 报告。

## 指标解释

- p50/p95/p99 为按请求计算的 nearest-rank 百分位，不是每个学生完成整个页面的时间。
- 吞吐量包括轮次间等待时间，不能直接当作系统峰值 RPS。
- 成功率同时检查 HTTP 状态，答卷读取另外核对 ID；并非对所有响应字段做完整业务验证。
- 只有 3 份模型回答时，p95 几乎等于最慢的一次，不具备稳定的分位数估计能力。
- `cpu.max` 为 `50000 100000` 时表示 0.5 核 CPU 时间配额，不是宿主机的物理核心数。
- `cpu.stat` 的 throttling 增量用于判断 CPU 配额限制；累计值不能直接当作本次测试数据。
- `memory.current` 是整个容器的占用，包括 PostgreSQL、Redis、API、worker、文件缓存和测试进程，不是单独 API 的内存。
- 费用字段为项目价格表估算；供应商实际账单需独立核对。

## 尚需独立覆盖

- 30 个真实微信账号在一分钟内登录和重试。
- 从外部负载机持续 30–60 分钟的稳定性测试。
- 30 人同时提交评分，以及模型限流时答案保留、排队、重试、教师复核的完整闭环。
- 教师实际成绩列表和导出接口负载；本工具不授予测试身份教师发布权限。
- 文件上传、DOCX/PDF 解析、对象存储下载，使用不同大小的合成材料。
- STT/TTS 的并发、音频流量、客户端录音状态。
- 手机弱网、断网重连、前后台切换和页面刷新。

不能仅根据 30 个用户读取成功，就宣布支持 30 人同时生成蓝图或实时评分。
