# 微信账号独立个人空间

日期：2026-09-22。后端版本保持 0.9.0。

## 已部署行为

- 当前 AutoDL 服务已设置 `WECHAT_REGISTRATION_MODE=personal`，公网状态接口已确认生效，`/ready` 返回 ready。
- 新微信账号完成真实 code2Session 验证后，自动创建“我的个人空间”，无需申请审批。
- 之前产生的、没有现有授权冲突的 pending 身份在下次真实登录时走相同流程，不需要用户重新注册。
- 每个新账号有唯一空间，授予 examiner，不授予管理员或 owner，不加入其他账号的空间。
- 原有 active 账号保持既有组织、权限和数据。暂停/禁用账号及撤销的成员权限不被自动恢复。
- 注册使用 PostgreSQL 行锁和稳定空间 ID；启用身份、成员、审计和登录会话在同一事务中完成。
- 补齐文档列表及证据接口的显式空间授权检查，和 PostgreSQL RLS 共同防护。

用户在 `D:\wechat` 对应项目重新编译后，再点微信登录即可。工作台自动选中唯一可用空间。若手机运行的是旧预览包，需要生成新预览；免审批后端行为本身无需等待客户端发布。

真实 PostgreSQL 检查使用 `deploy/verify-wechat-personal-rls.py`，数据库名称严格限制为 `aiex_wechat_personal_*_test`。只复制原数据库结构，不复制用户数据；验证后已删除本次新建测试库。未修改正在服务的数据库结构、角色或 RLS 策略。没有调用付费模型。

## 部署和回滚

本次部署四个服务端文件：config.py、services/wechat.py、wechat_api.py、main.py。部署前检查远端摘要，原文件备份在：

```text
/root/autodl-tmp/ai-examiner-mvp/ai-examiner-v0.9-staging/.wechat-backup-20260922T091036Z
```

私有 `wechat.env` 的副本仅保存在上述服务器私有目录，权限 0600，未复制进源码。API 经进程身份核对后优雅停止，用原启动脚本恢复；数据库、文件、存储服务不变。

`D:\wechat` 只同步登录页、工作台提示和进度错误文案，AppID、域名等配置保持不变；本地旧文件保存在仓库 `.ui-review/wechat-personal-*-before-*`。

停用新账号自助注册：在服务器私有配置改回 `WECHAT_REGISTRATION_MODE=approval`，重启 API。已经启用的空间不会因此被删除或禁用；需要禁用时显式执行账号/会话管理。严禁删除数据库或关闭 RLS 作为回滚。
