# 蓝图生成重复重试与耗时修复

日期：2026-10-23。应用版本保持 0.9，Planner 提示词修订为 v8。

## 实际故障

在现有 AutoDL 部署上，以非超级用户、无 BYPASSRLS 的应用数据库角色，
按授权租户上下文查询任务与模型治理账本。未读取或输出 API Key，也未修改预算。

- 最近一次 726 字材料任务，排队 0.09 秒，总耗时约 363.29 秒。
- 后台任务执行 3 次，发生 12 次 qwen-plus 调用。
- 前两次执行的局部措辞修正耗尽，服务将其包装成可重试的模型输出异常，
  Celery 又从全文蓝图生成开始重跑。局部重试与整任务重试相乘。
- 上一次同材料任务执行 2 次，耗时约 190.60 秒。
- 单看 `UsageEvent` 会遗漏失败事务中回滚的调用，因此最初看起来存在
  大量无法解释的额外等待。独立提交的 `ModelUsageLedger` 记录了这些调用。
- 检查时未发现 PostgreSQL 阻塞；小程序 2.5 秒轮询也不是本次分钟级延迟主因。

## 修改范围

1. `PlannerRepairExhausted` 明确表示已用完内部修正预算。
2. 蓝图服务将该错误标记为不可自动整任务重试。普通未经内部修正的模型输出错误
   和网络瞬时故障仍保留原来的有限重试机制。
3. 只规范化明确的“这一结果是否成立？为什么？”等中文判断加裸理由句式：
   改成“针对这一结果是否成立，你的判断依据是什么？”。不删除判断、依据要求或前文。
4. 不自动改写两个不同问题、带特定理由对象的追问、条件不明确的句子或引用中的问句。
   这些仍需模型修正，并通过原有单问题校验。
5. 修正提示加入具体失败槽位和被拒绝的完整补丁，避免只收到笼统报错后原样重复。
6. 补丁仍整批校验后应用；不得修改评分点、来源页码、知识点或未被授权修改的题目。

保持 qwen-plus、非思考模式、全文输入、模板题量、难度范围与租户权限不变。
没有改成 mock，没有缩短材料，也没有将不合格蓝图当成成功结果。

  未为缩短耗时删除回答要点，也不能因此声称全部内容质量验收通过。

  这说明剩余长尾仍包括初次长 JSON 生成和结构修正。
- 未做手机端全链路计时、长论文压力测试或专家语义一致性复核。
  这些结果不代表一分钟 SLA，也不代表七模板真实模型验收已重新完成。

备份目录：`.planner-retry-backup-i3jtlua3`，位于现有服务器项目根目录。
未修改数据库结构、模型密钥、组织权限或原有业务记录；没有重新触发旧任务。

本次属于服务端修复，小程序不需要重新编译。新任务使用新逻辑，既有蓝图不重写。
