# 小程序语音问答

2026-10-21 更新：新增独立的[千问实时语音实现与验收记录](REALTIME_VOICE.md)。
下文仍描述按轮 ASR/TTS 备用模式，不能据此认定实时模型已通过验收。

日期：2026-10-20。后端版本维持 0.9.0。没有数据库结构迁移。

## 本次范围

原生小程序采用按轮语音问答：

1. 点击“朗读题目”，播放服务端当前题目；长题目按最多 500 字分段播放。
2. 点击“语音回答”，首次确认数据处理说明、微信隐私授权和麦克风权限。
3. 再次点击“结束录音”。每段最多 60 秒，16 kHz 单声道 MP3，上传上限 2 MB。
4. 录音识别为文字，追加到回答草稿；可以修改或者再次录音追加。
5. 用户点击“确认并提交回答”，沿用现有文字提交、评分和教师收集流程。

支持个人答辩、学生正式答卷和隔离的教师试答。教师查看学生成绩页不显示录音控件。
开始录音会停止题目播放。切题、切到后台、离开页面或取消时停止麦克风/音频并忽略晚到响应。
没有自动提交、自动续录或自动抢话，语音识别失败不会伪造答案或切换 Mock。

**这不是全双工实时通话**：没有 WebRTC、流式转写或自动轮次检测。识别耗时与回答模型耗时分别发生，
不能用协议测试宣称具有 ChatGPT Voice 的实时体验。后续实时版需单独验证原生流式录音、播放缓冲、
服务端 WebSocket、回声和中断恢复，并保持考试问题和评分受现有业务流程控制。

## 服务端配置

使用现有服务器中的 `DASHSCOPE_API_KEY`，不在小程序中放模型 Key：

```dotenv
WECHAT_SPEECH_ENABLED=true
WECHAT_ASR_MODEL=qwen3-asr-flash
WECHAT_TTS_MODEL=qwen3-tts-flash
WECHAT_TTS_VOICE=Cherry
WECHAT_TTS_BASE_URL=https://dashscope.aliyuncs.com/api/v1
WECHAT_SPEECH_TIMEOUT_SECONDS=40
WECHAT_SPEECH_CALL_BUDGET_USD=0.05
```

ASR 沿用 `DASHSCOPE_BASE_URL` 的 OpenAI 兼容地址；TTS 使用独立的 DashScope 原生地址。
两个地址与 Key 必须属于相同地域/工作空间。服务端需联网访问千问和返回音频的 OSS 域名。
模型名称可以配置，但变更后应重新验证协议、音色、费用和组织白名单。

**模型治理不会被绕过或自动放宽。** 管理员在实际承担费用的组织中增加以下允许项，保留原有其他规则：

```json
[
  {"provider": "qwen", "model_pattern": "qwen3-asr-flash", "tasks": ["voice"]},
  {"provider": "qwen", "model_pattern": "qwen3-tts-flash", "tasks": ["voice"]}
]
```

学生考试的语音调用计入出题教师的组织/项目，调用者仍记录为该学生；个人答辩计入当前授权工作空间。
沿用组织的限流、并发、资料密级和预算审批。上述 `0.05` 是每次请求保守预算估算，不是价格报价或实际账单；
语音按时长/字符计费，不能套用 `qwen-plus` 的文本 Token 单价。失败调用保留保守预留估算，
长题每个分段分别计一次。管理员应依据当前地域价格和实际账单调整，当前实现不提供精确语音账单对账。
使用量账本记录模型、耗时、供应商返回的 Token；不把字符数伪装成 Token。

开关开启且有 Key 只代表“已配置”，不代表模型允许调用。组织拒绝返回 403，额度/限流返回原治理错误。
关闭开关立即恢复纯文字功能，不需要回滚数据库。

## API 契约

资源前缀：`/api/v1/wechat/voice/{kind}/{resource_id}`。
`kind` 为 `session`、`attempt`、`preview`；所有接口要求有效身份。

| 方法 | 路径 | 输入与输出 |
| --- | --- | --- |
| GET | `/context` | 当前题目指纹、配置状态、时长限制和模型名 |
| POST | `/transcribe` | multipart `file` + `question_key`，返回 `text`，不提交答案 |
| POST | `/speech` | JSON `question_key` + `segment`，返回当前题目的 WAV Base64 和分段信息 |

题目指纹由资源、当前位置和内容构成。客户端不能指定朗读文本或参考答案；
不匹配指纹返回 409，越权返回 403/404，录音格式/长度无效返回 413/422。
教师试答独立授权，不允许学生读取；学生也不能借该 API 进入教师资料空间。
个人会话沿用组织成员和 `session.conduct` 能力检查。

没有新增语音答卷表。录音在微信临时文件和服务端 multipart 临时缓冲中处理，处理结束后清理，
不进入上传材料目录、对象存储、成绩库或应用日志。供应商保存政策仍按实际账户协议执行，
不能承诺供应商零保留。确认后的文字与普通答案一样进入现有保留/删除流程。
合成音频只在客户端临时文件中播放，结束、取消或离开页面时删除；异常退出时清理由微信系统接管。

## 结束录音状态与重录修复（2026-10-23）

用户再次报告“上一段录音正在结束”。本次在本地控制器测试中复现两个状态错误：

- 连续点击两次“结束录音”，第二个排队点击在微信 Stop 回调到达前把界面重置为空闲。
- 取消录音立即返回空闲，但原生录音器仍持有麦克风，紧接着重录会被全局所有权拦截。

修复前这两个新增测试均失败，修复后通过。不能据此断言本次手机上的故障只由上述两项导致；
缺少手机运行日志，仍需新预览包真机确认。

### 当前行为

1. 授权、结束录音、转写中的重复点击不再打乱状态，也不重复发起转写。
2. 取消后先等待原生 Stop/Error 确认；旧录音不会上传。另一页面最多等待 5 秒再返回恢复提示。
3. 页面切回前台检查实际时钟期限，不依赖后台可能暂停的定时器。
4. 开始/结束回调超时后恢复文字操作，但保留旧录音的逻辑所有权和回调。
   微信原生 Stop 事件没有录音 ID，不能仅因超时就释放锁，把迟到的上一段音频路由给新录音。
5. 用户再次点击语音回答时可有界重试停止；收到原生结束确认后才启动新录音。
   原生组件始终无响应时提示关闭并重新打开小程序，或继续文字回答，不假装恢复成功。
6. 迟到的 Start 会再次停止麦克风；迟到的取消录音会删除临时文件，不回填、不提交、不产生评分。

本节替代 10 月 22 日“超时即清理/释放”的恢复方式。正常停止后的转写、题目朗读、
权限和原生 MP3 参数不变，录音格式 422 问题不在本次修复范围。
