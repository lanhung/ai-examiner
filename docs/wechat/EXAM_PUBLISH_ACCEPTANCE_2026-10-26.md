## 真实模型结果

题目要求解释开发集调参与测试集隔离如何防止评估偏差。学员回答强调冻结参数、防止测试信息泄漏、保持两套系统配置相同，以及小样本和跨领域推广限制。

- 本次答案模型调用：`answer_analyzer / qwen / qwen-plus`，1 次。
- 模型延迟：24,146 ms；输入 2,354 token，输出 1,067 token。
- 题目评分：4.9/5；考试页面显示 98/100，尚未人工复核。
- 三个要点均被判定为语义等价覆盖，没有因未逐字复述标准措辞扣为遗漏。
- 题目、回答和主要评价说明均为中文；未观察到对话规则泄露。

准备阶段蓝图后台任务耗时约 65.62 秒，生成 6 个候选问题，本次只发布第 1 题；记录有 3 条 qwen-plus Planner 调用。该时间不代表所有材料的速度，也不包含完整手机操作时长。24.146 秒是评分模型调用耗时，不是手机端端到端延迟。

原始探针使用“方法 + 路径”作为检查字典键，同一路由的后一次请求会覆盖前一次状态。因此原始结果中 answers 路由最后显示的 409 是刻意发送的冲突请求，不是首次评分失败。首次提交、重复提交和冲突提交均分别执行了预期状态断言，整次探针 `passed=true`。

## 发现与修复

### 学生报名在 PostgreSQL RLS 下返回 500

旧报名代码使用 `db.refresh(exam, with_for_update=True)`。学生可以通过 SELECT 策略读取已发布考试，但不能通过教师专属 UPDATE 策略；请求 UPDATE 行锁导致刷新拿不到目标行，抛出 `InvalidRequestError: Could not refresh instance`。仅用本地 SQLite 测试无法充分发现此问题。

修复位于 `src/ai_examiner/school_api.py`：

1. PostgreSQL 下使用按考试 ID 派生的事务级 advisory lock。
2. 报名与关闭共用锁，使“检查可报名状态”和“关闭考试”按序执行。
3. 报名获取锁后执行普通 SELECT，使用 `populate_existing=True` 重新读取状态。
4. 如果考试已关闭或 RLS 已使其不可见，返回 409，不再请求学生 UPDATE 权限。

保留原身份授权、RLS、唯一约束和请求幂等机制。未增加学生权限，未禁用 RLS，未执行数据库迁移。

### 回归测试

新增三个用例：

- `test_admission_never_requests_student_update_lock`
- `test_close_winning_admission_lock_blocks_new_attempt`
- `test_postgres_admission_lock_is_stable_and_transaction_scoped`

本地运行结果：`tests/test_school_exams.py` 共 18 passed；修改的 Python 文件 Ruff 通过。真实服务器通过独立学生身份再次验证报名、作答与成绩保存，补充本地测试的 PostgreSQL/RLS 覆盖。

本次未在生产数据库运行 pytest；测试夹具不得指向线上数据库。
