# 小程序教师端与学生端

状态：预览功能已部署到现有 AutoDL 服务，业务代码已同步至本机 `D:\wechat`。
服务端仍为 0.9.0，未创建正式发布 Tag；本轮新增功能尚未推送 GitHub。

## 本轮范围

- 登录后进入考试大厅。所有已登录的有效账号可查看已发布考试。
- 教师由服务器管理员显式开通；已有个人空间的 `examiner` 成员不会自动成为教师。
- 教师在自己的授权空间上传 PDF、DOCX、PPTX、TXT、Markdown，生成蓝图并确认后发布。
- 发布前必须确认材料可公开给已登录学生；受限级别 `restricted` 材料禁止发布。
- 考试材料可阅读提取正文，PDF/DOCX/PPTX 可授权下载到微信临时文件并预览。
- 每个学生每场考试一份答卷，按固定顺序答题。姓名、学号由学生填写，不代表实名认证。
- 完成后成绩自动进入发布教师的成绩列表，教师可看原答案、逐题评价并复核总分。
- 学生不能看其他学生答卷、参考答案库或教师私人空间。
- 原个人答辩工作台保留，不自动共享原有项目。

本轮不是班级系统：没有邀请码、班级名单、定时考试、重考、监考或正式成绩认证。
不支持语音考试；个人答辩与考试答卷为独立流程。

## 操作顺序

### 教师

教师账号同时保留学生端。在首页点击“学生端 / 教师端”可来回切换，无需退出登录；
这只是切换页面与考试列表，不会撤销教师身份，也不会新建账号或公开原有材料。
从考试准备或成绩详情页先返回首页，再选择“学生端”。普通学生不会显示教师切换入口。

1. 管理员开通身份后重新进入小程序，在首页切换“教师端”。
2. “准备材料与发布考试”进入授权教师空间。
3. 创建项目、上传材料、选择真实模型、生成蓝图，检查问题和材料内容。
4. 填写考试名称、教师署名、考试要求和题数，确认公开材料后发布。
5. “我发布的考试”中查看学生答卷和成绩；刷新即可获取最新状态。
6. 关闭报名后，不再接收新学生，但已开始的答卷可以继续完成。

### 学生

1. 登录后在考试大厅查看考试和材料。
2. 填写姓名及可选学号，确认将姓名、学号、答卷和成绩交给发布教师。
3. 点击“参加 / 继续考试”，逐题提交回答。
4. 网络异常时先刷新，或用原提交编号确认结果；不会新建第二份答卷。
5. 全部完成后查看自己的初评结果；教师复核后显示复核成绩和理由。

### 教师试答（2026-10-15 新增）

一个教师账号即可在自己发布的考试详情点击“开始试答”，用实际评分模型逐题作答，
然后返回考试详情查看试答分数。学生端查看本人发布的考试也显示试答入口，不再显示
普通报名表。普通报名接口仍拒绝教师参加自己的考试。

- 试答使用独立的 `teacher_exam_previews` 表，绝不写入 `school_attempts`。
- 正式学生成绩列表、人数和学生个人进度不包含试答；页面始终标注“教师试答”。
- 每场考试保留一份可继续的教师试答，重复打开不新建，不提供重置/无限重考。
- 题目、评分标准、模型、预算和限流沿用该考试的配置，实际调用会产生模型费用。
- 所有试答请求都验证发布教师本人、教师授权及工作空间；学生和其他教师不能访问。
- 评分失败保留原答案；可手工给该题评分以恢复试答，结果明确标记人工来源。
  人工恢复不能作为真实 AI 评分通过的证据。
- 单账号试答验证题目、评分、持久化和教师展示，不等于两个账号间的权限隔离实机验收。

迁移 `20261015_0019` 只新增试答表及强制 RLS，不改写既有考试、学生答卷或账号权限。
回滚业务代码时保留试答表；含试答数据时降级迁移会拒绝删除，避免误删记录。
考试相关项目导出将试答放在独立数据表中，不能把它合并为正式成绩。

## 身份开通

运行环境需要管理员数据库连接。生产运行账号对 `teaching_grants` 只有 SELECT 权限，
小程序没有授予教师权限的 API。不要在小程序代码放管理凭据。

账号编号可在小程序考试大厅底部查看。组织必须已存在，账号必须有该组织的有效
examiner/admin/owner 成员关系。开通教师身份不会赋予组织管理员权限。

```bash
python -m ai_examiner.teaching_cli \
  --principal-id '<已核对的账号编号>' \
  --organization-id '<该账号的授权空间编号>' \
  --operator '<实际管理员标识>' \
  --confirm
```

撤销时增加 `--revoke`。不能通过这条命令将教师随意迁移到别人的空间。
新建教师建议使用独立空间；旧的共享组织仍沿用既有工作台权限，不能当作个人空间使用。

## 数据与权限

迁移：`20260924_0018_school_exams`，接续 `20260810_0017`，新增四张表：

| 表 | 内容 | 访问控制 |
|---|---|---|
| teaching_grants | 教师授权及指定空间 | 本人查询，管理员 CLI 写入 |
| published_exams | 已公开的考试元数据及材料正文快照 | 登录后已发布可见；关闭后本人答卷仍可追溯 |
| exam_papers | 题目、评分要点、模型、源文件引用 | 私有；不通过学生响应返回 |
| school_attempts | 学生身份、原始答卷、初评分、复核分 | 本人和发布教师；组织管理员仅经现有授权导出流程访问 |

PostgreSQL 新表启用并强制 RLS。应用每个请求先验证登录身份，学生参加考试不加入
教师组织，而是基于已验证的发布记录限定内部读取范围。客户端传入的组织头不能替代该检查。
教师操作还检查授权、组织状态、成员状态和资源所有者。所有列表分页，每页最多 50 条。

材料发布后题目与评分要点固定，不会因修改原蓝图而漂移。公开材料正文有独立快照；
原文件引用受保护。学生响应仅包含当前问题，考试中不提前给出本题评分要点。

## 评分与可靠性

- 沿用 AnswerAnalyzer、Evaluator、Prompt Registry 和受治理的 Provider。
- 教师选定模型，学生不能换模型、提交分数或修改题目。发布接口拒绝 Mock。
- 调用归属教师的项目/组织，实际作答人为学生，受现有配额与限流控制。
- 逐题 0–5 分，等权平均乘 20 得到 0–100 的 AI 初评分。
- 初评不是正式考试裁决。教师复核必须填写理由，原初评分保留，复核写入审计。
- 发布请求使用唯一幂等编号；每个考试和学生有唯一答卷约束。
- 回答用请求编号和题目位置校验，数据库先持久化评分占位，再调用模型。
- 模型失败将答卷置为 `needs_review`，保留答案，不自动重复付费请求。
- 教师可以给失败的原答案人工评分；进程中断后持续 `grading` 超过 30 分钟也可人工恢复。
- 人工恢复和延迟模型响应使用条件更新，防止两个结果互相覆盖。
- 初评和复核接口不接受客户端自报身份或角色；额外输入字段拒绝。

## 升级与回滚

1. 备份数据库及现有代码；保留 `.env`、对象存储、登录配置。
2. 使用管理数据库连接执行 `alembic upgrade head`，再启动服务端。
3. 确认 `/api/v1/school/me` 未登录返回 401，而不是 404/500。
4. 更新小程序业务文件，保留本机 `config.js`、AppID 和开发工具私有配置。
5. 开通已核对的教师账号，用两个不同账号进行教师发布和学生作答验收。

回滚代码时保留新增表及成绩，不要直接执行 downgrade；降级迁移会删除四张新表。
已发布考试引用的项目暂时禁止删除，避免先删除物理文件再因数据库约束失败。
考试专用保留/删除审核与按学生导出尚未建设，不应将本预览版用于有强制清退要求的正式考试。
